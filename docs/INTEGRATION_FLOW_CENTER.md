# مرکز جریان اتصال‌ها

صفحهٔ `MerchantSimulation/Dashboard` اکنون به‌عنوان مرکز عملیات اتصال‌ها عمل می‌کند. این صفحه برای باسلام ساخته شده اما قراردادهای آن provider-neutral است و با اضافه‌شدن دیجی‌کالا و ترب نیازی به تغییر مدل نمایش ندارد.

## منبع داده و سربار

برای جلوگیری از ایجاد جدول لاگ موازی، UI از همان رکوردهای عملیاتی موجود استفاده می‌کند:

| بخش UI | منبع SQL | کاربرد |
|---|---|---|
| وب‌هوک ورودی | `IntegrationWebhookInbox` | ورود رویداد از پلتفرم، وضعیت پردازش و خطا |
| جاب پایدار | `IntegrationScenarioJobs` | درخواست‌های لایو، ایونتی، دستی، دوره‌ای و یکسان‌سازی اولیه |
| اثر خروجی | `IntegrationOutbox` | ارسال تغییر به پلتفرم و retry/dead-letter |
| اجرای sync | `IntegrationSyncRuns` | اجرای کامل کاتالوگ و تعداد اقلام |

فقط projectionهای محدود و بدون `PayloadJson` یا credential به داشبورد برمی‌گردد. جاب‌ها حداکثر ۵۰ رکورد و فید هر نوع رویداد حداکثر ۳۰ رکورد دارد؛ بنابراین polling صفحه، full scan یا نگهداری event log جدید ایجاد نمی‌کند.

## لایو

`GET /MerchantSimulation/Live` با scope غرفهٔ انتخاب‌شده، snapshot جدید را برمی‌گرداند. صفحه هر ۵ ثانیه آن را poll می‌کند و فقط metric، فید و جدول صف را به‌روزرسانی می‌کند؛ در خطای موقت شبکه، صفحهٔ فعلی حفظ می‌شود.

## سیاست نگهداری

این صفحه diagnostic و read-only است. retry/replay از UI انجام نمی‌شود. پاک‌سازی رکوردهای قدیمی باید با retention job جداگانه انجام شود و نباید رکوردهای dead-letter یا خطاهای قدیمی را پیش از ثبت audit حذف کند.
